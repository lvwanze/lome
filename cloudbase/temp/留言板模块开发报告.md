## 三、技术方案实现说明(对应方案第六节)

### 3.1 与现有代码风格完全一致

- 复用 `common.js`:`getParams`(兼容 HTTP 网关/CLI 直调)、`getUserId`/`getAuthUser`(JWT 鉴权 + 查询用户 + 返回 partnerId)、`firstDoc`、`inCoupleScope`
- 统一响应 `{ code, message, data }`,成功 `code=0`
- `@cloudbase/node-sdk` 服务端直连数据库,依赖版本与日历模块相同(`^2.0.0` + `jsonwebtoken ^9.0.0`)

### 3.2 数据隔离(V1 强制)

- 列表查询强制双重条件:`我的留言 WHERE authorId=自己 AND partnerId=伴侣`;`Ta的留言 WHERE authorId=伴侣 AND partnerId=自己`
- 详情仅 `inCoupleScope`(作者或伴侣)可见
- 编辑/删除仅作者;回应/删除回应仅对应角色;未绑定伴侣直接返回 4006

### 3.3 实现取舍说明

| 设计点 | 实现方式 | 原因 |
| --- | --- | --- |
| 回应存储 | 内嵌于留言文档(replyContent/replyAuthorId/replyTime) | 方案 3.1 数据模型即内嵌字段;每条留言仅保留一条回应,覆盖式更新即可,无需单独集合 |
| `replyId` 字段 | 预留未使用(索引已建) | 字段表中标注"若本条是回应"属独立回应文档模型;V1 采用内嵌,该字段与 idx_reply 为后续 P2 扩展预留 |
| 作者昵称/头像 | 详情/列表实时查 users 集合补充 | users 无 avatar 字段,`authorAvatar` 返回空串,后续用户体系补充头像后无需改接口 |
| 错误码 | 4001 未登录/Token无效、4002 用户不存在、4004 内容为空或超限、4005 留言不存在、4006 无权限、500 系统错误 | 4001/4002/500 沿用 common.js 现有约定;方案 4.4 的 4003(Token过期)归入 4001 处理,保持与日历模块客户端兼容 |

### 5.1 路由映射

> 说明:云开发网关按**路径前缀**路由,不支持按 HTTP 方法分发,Event 函数也不支持 `{id}` 路径参数。方案 4.1 中存在方法复用(GET/POST 共用 `/api/v1/messages` 等),故按日历模块惯例「一函数一操作路径」映射,messageId 通过 body/query 传递。

| 方案接口(4.1) | 实际路由路径 | 上游函数 |
| --- | --- | --- |
| GET 获取列表 `/api/v1/messages` | `/api/v1/messages/list` | messageList |
| POST 发布 `/api/v1/messages` | `/api/v1/messages/create` | messageCreate |
| GET 详情 `/api/v1/messages/{id}` | `/api/v1/messages/detail` | messageDetail |
| PUT 编辑 `/api/v1/messages/{id}` | `/api/v1/messages/update` | messageUpdate |
| DELETE 删除 `/api/v1/messages/{id}` | `/api/v1/messages/delete` | messageDelete |
| PUT 已读 `/api/v1/messages/read` | `/api/v1/messages/read`(与方案一致) | messageRead |
| POST 回应 `/api/v1/messages/{id}/reply` | `/api/v1/messages/reply` | messageReply |
| DELETE 删除回应 `/api/v1/messages/{id}/reply` | `/api/v1/messages/replyDelete` | messageReplyDelete |
